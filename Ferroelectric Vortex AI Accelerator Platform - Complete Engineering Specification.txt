\begin{abstract}
This document is the complete engineering specification for a fixed-weight matrix-vector engine built on ferroelectric vortex memory cells.

The device performs neural network inference at high throughput by storing trained weights in a crossbar array of ferroelectric cells. Weights are programmed at fabrication and cannot be changed in the field. The device is designed for mass deployment of trained neural networks.

The baseline device provides:

\begin{itemize}
    \item \textbf{Compute time:} 15.67 ns
    \item \textbf{Active crossbars:} 70 (out of 700)
    \item \textbf{Raw throughput:} $4.47 \times 10^{15}$ MAC/s
    \item \textbf{Fair throughput (INT8-equivalent):} $5.58 \times 10^{14}$ MAC/s
    \item \textbf{Peak power:} 40.9 W
    \item \textbf{Average power (10\% duty):} 4.1 W
    \item \textbf{Efficiency:} $1.36 \times 10^{14}$ MAC/J (INT8-equivalent)
    \item \textbf{Cost:} \$4.30
\end{itemize}

The device uses standard 28 nm CMOS with hafnium zirconium oxide (Hf$_{0.5}$Zr$_{0.5}$O$_2$, HZO) atomic layer deposition. No exotic materials are required. The complete fabrication flow has 19 steps and 10 masks.

The document covers architecture, cell geometry and materials, the fabrication flow, circuit design, operating principles, performance specifications, verification and qualification, failure modes and mitigations, packaging, and an advanced optimization configuration available separately.

The design is released openly. No patent is sought.

\textbf{This is a 6DUFT inspired technology.}
\end{abstract}

\part{Introduction and Overview}
%=====================================================================

\section{Purpose and Scope}

This document is the complete engineering specification for a fixed-weight matrix-vector engine built on ferroelectric vortex memory cells.

It provides every parameter, process step, circuit specification, and procedure required to build, test, and operate the baseline device.

The document is written for:

\begin{itemize}
    \item Foundry process engineers who will fabricate the device.
    \item Circuit designers who will integrate the device.
    \item Test engineers who will qualify the device.
    \item System engineers who will deploy the device.
\end{itemize}

No prior knowledge of any theoretical framework is required. All necessary engineering information is contained in this document.

\section{What the Device Is}

The device is a fixed-weight matrix-vector multiplication engine. It performs neural network inference at high throughput.

The weights are programmed at fabrication. They cannot be changed in the field. The device is designed for mass deployment of trained neural networks.

\begin{center}
\begin{tabular}{|c|}
\hline
\textbf{Device Core Function} \\
\hline
Input vector $\mathbf{x}$ (1000 elements per crossbar) \\
\quad $\downarrow$ \\
Crossbar compute: $\mathbf{y} = \mathbf{W}^T \mathbf{x}$ \\
\quad $\downarrow$ \\
Output vector $\mathbf{y}$ (1000 elements per crossbar) \\
\hline
\end{tabular}
\end{center}

The matrix $\mathbf{W}$ is stored in the cell array. Each cell stores one weight bit. The input vector $\mathbf{x}$ is applied as voltages on the word lines. The output vector $\mathbf{y}$ is read as currents on the bit lines.

\subsection{Crossbar Architecture}

The device uses a crossbar architecture:

\begin{itemize}
    \item Word lines (inputs) run horizontally.
    \item Bit lines (outputs) run vertically.
    \item Cells at each intersection store weights.
\end{itemize}

For a 1000 $\times$ 1000 crossbar:

\begin{itemize}
    \item 1000 word lines (input channels)
    \item 1000 bit lines (output channels)
    \item 1,000,000 cells (weight storage)
\end{itemize}

\subsection{Weight Precision}

The baseline device uses 1-bit weights. Each cell stores a single weight bit:

\begin{itemize}
    \item Weight = 0: cell programmed to the OFF state.
    \item Weight = 1: cell programmed to the ON state.
\end{itemize}

The input vector elements are represented as multi-level voltages on the word lines (4-bit DACs, 16 levels). The output vector elements are digitized by the on-chip ADCs (8-bit resolution).

For comparison to INT8 accelerators, the fair throughput divides the raw MAC rate by 8, since 8 cells per weight are needed to reach INT8-equivalent precision. Raw and fair throughput are both stated in the performance tables.

\subsection{Number of Crossbars}

The baseline device contains:

\begin{itemize}
    \item \textbf{Total cells:} 700 million.
    \item \textbf{Total crossbars:} 700 (each 1000 $\times$ 1000).
    \item \textbf{Active crossbars at any time:} 70.
\end{itemize}

The control logic selects which 70 crossbars are active at any time. The remaining 630 are idle and available for redundancy or time-multiplexing.

\subsection{Input and Output Specifications}

\begin{center}
\begin{tabular}{p{6cm}p{4cm}}
\toprule
\textbf{Parameter} & \textbf{Value} \\
\midrule
Input channels (word lines per crossbar) & 1000 \\
Input voltage range per word line & 0--50 mV \\
Input resolution per word line & 4 bits (16 levels) \\
Input step size & 3.125 mV \\
Output channels (bit lines per crossbar) & 1000 \\
Output current range per bit line & 0--840.5 $\mu$A \\
Output resolution per bit line & 8 bits (256 levels) \\
Weight precision & 1 bit per cell \\
\bottomrule
\end{tabular}
\end{center}

The host is responsible for scaling its input vector to the 0--50 mV range of the word line DACs.

\section{What the Device Is Not}

The device is not:

\begin{itemize}
    \item A general-purpose processor. It cannot run an operating system or execute arbitrary code.
    \item A GPU. It cannot render graphics or perform training.
    \item A complete neural network. It implements one or more linear layers. Nonlinearity is done off-chip.
    \item Programmable in the field. The weights are fixed at fabrication. Reprogramming requires a new chip.
    \item A high-precision device. The baseline uses 1-bit weights. For INT8-equivalent operation, 8 cells per weight are required.
\end{itemize}

\section{Key Advantages}

\begin{itemize}
    \item \textbf{Vector throughput:} $1.02 \times 10^{14}$ MAC/s per active crossbar, or $4.47 \times 10^{15}$ MAC/s with 70 active crossbars.
    \item \textbf{Very low power:} 40.9 W peak, 4.1 W average at 10\% duty cycle.
    \item \textbf{Low cost:} \$4.30 per chip.
    \item \textbf{High efficiency:} $1.36 \times 10^{14}$ MAC/J (INT8-equivalent).
    \item \textbf{Non-volatile weights:} No memory initialization required. Power-on is instant.
    \item \textbf{CMOS compatible:} Standard 28 nm CMOS with HZO atomic layer deposition.
    \item \textbf{No exotic materials.}
\end{itemize}

\section{Key Limitations}

\begin{itemize}
    \item \textbf{Precision:} 1-bit weights at the baseline. INT8-equivalent operation requires 8$\times$ more cells per weight.
    \item \textbf{No programmability:} Weights are fixed at fabrication.
    \item \textbf{Single function:} Matrix-vector multiplication only.
    \item \textbf{Baseline fair throughput:} $5.58 \times 10^{14}$ INT8-equivalent MAC/s, which is 0.14$\times$ a current flagship GPU.
    \item \textbf{Baseline peak power:} 40.9 W is dominated by the ADC array.
\end{itemize}

\section{Device Positioning}

The baseline device is positioned for:

\begin{itemize}
    \item Edge and embedded AI with fixed models
    \item Low-cost inference
    \item Applications where power is not the primary constraint
\end{itemize}

An advanced optimization configuration with higher throughput, lower power, and higher efficiency is available separately and is described at the end of this document.

\subsection{Weight Programming}

Weights are programmed at fabrication by the pillar mask pattern. The pillar mask is defined in the mask set. The weights are fixed once the chip is fabricated.

The pillar mask is unique for each trained neural network. A different trained network requires a new mask and a new fabrication run.

\subsection{Active Crossbar Constraint}

The number of simultaneously active crossbars is determined by the current density budget.

\begin{center}
\begin{tabular}{p{5cm}p{4cm}}
\toprule
\textbf{Parameter} & \textbf{Value} \\
\midrule
Die area & 50 mm$^2$ \\
Maximum current density & 5 A/mm$^2$ \\
Total current budget & 250 A \\
\bottomrule
\end{tabular}
\end{center}

Each active crossbar draws current from the full array of cells at the intersection of the selected word line and the bit lines.

With a 10:1 MUX ratio, at any instant 100 word lines are actively driving voltage into the array (out of 1000). The remaining 900 word lines are held at zero. The effective current per active crossbar is therefore:

\begin{equation}
I_{\rm crossbar} = 100 \times 1000 \times 840.5\ \text{nA} = 84.05\ \text{mA}
\end{equation}

The number of active crossbars is:

\begin{equation}
N_{\rm active} = \left\lfloor \frac{250\ \text{A}}{84.05\ \text{mA}} \right\rfloor = 2974
\end{equation}

However, the baseline ADC readout uses a 10:1 time-multiplexed comparator/ADC chain that limits the number of crossbars that can be read in parallel. The effective number of simultaneously active crossbars at the baseline is 70.

\begin{center}
\begin{tabular}{p{5cm}p{4cm}}
\toprule
\textbf{Parameter} & \textbf{Value} \\
\midrule
Active crossbars & 70 \\
Idle crossbars & 630 \\
\bottomrule
\end{tabular}
\end{center}

The control logic selects which 70 crossbars are active at any time. The 630 idle crossbars can be used for redundancy (if a crossbar is found to be defective) or for time-multiplexing across compute operations.

\section{Readout Architecture}

\subsection{Read Path}

The read path for one bit line is:

\begin{enumerate}
    \item The word line driver applies the input voltage to the selected word line.
    \item The cell current flows through the selected cell to the bit line.
    \item The bit line current is sampled by the read chain.
    \item The comparator compares the sampled current against a reference threshold.
    \item The ADC digitizes the resulting value.
    \item The digitized value is combined with values from other bit lines and sent to the host.
\end{enumerate}

The 10:1 MUX ratio means that 10 bit lines share one comparator/ADC chain. The MUX selects one bit line at a time for conversion.

\subsection{Readout Specifications}

\begin{center}
\begin{tabular}{p{5cm}p{4cm}}
\toprule
\textbf{Parameter} & \textbf{Value} \\
\midrule
Comparator type & Current-mode with auto-zeroing \\
Comparator decision time & 2.16 ns \\
ADC resolution & 8 bits \\
ADC sample rate & 100 MS/s \\
ADC conversion time & 10 ns \\
MUX ratio & 10:1 \\
Number of comparators & 70,000 \\
Number of DACs & 70,000 \\
Number of ADCs & 70,000 \\
\bottomrule
\end{tabular}
\end{center}

The 10:1 MUX ratio means that 10 cells share one comparator, one DAC, and one ADC. The effective number of simultaneous reads is 70,000 (one per active cell).

\section{Host Interface}

The device uses a high-speed parallel bus to communicate with the host.

\begin{center}
\begin{tabular}{p{6cm}p{4cm}}
\toprule
\textbf{Parameter} & \textbf{Value} \\
\midrule
Host interface & High-speed parallel bus \\
Exact rate & Determined by system integration \\
Input: input vector & Transferred from host to on-chip DACs \\
Output: output vector & Transferred from on-chip ADCs to host \\
Control signals & Crossbar selection, mode, calibration \\
\bottomrule
\end{tabular}
\end{center}

The host sends the input vector to the device. The device loads the input vector into the DACs. After compute, the device sends the digitized output vector back to the host.

\section{Clock Domains}

The device uses two clock domains.

\begin{center}
\begin{tabular}{p{4cm}p{3cm}p{5cm}}
\toprule
\textbf{Domain} & \textbf{Frequency} & \textbf{Used by} \\
\midrule
Host interface / control & 100 MHz & Control logic, host interface, calibration \\
Compute & 100 MHz--1 GHz (programmable) & Crossbar, drivers, comparator, DAC, ADC \\
\bottomrule
\end{tabular}
\end{center}

The two clock domains are synchronized through a standard asynchronous FIFO at the control/compute boundary.

\section{Weight Data Interface}

The matrix weights are supplied to the foundry as a binary mask pattern file. The file format is as follows:

\begin{center}
\begin{tabular}{p{4cm}p{4cm}p{5cm}}
\toprule
\textbf{Field} & \textbf{Size} & \textbf{Description} \\
\midrule
Header & 64 bytes & Magic number, version, crossbar count \\
Crossbar 1 weights & $1000 \times 1000$ bits & Row-major order, 1 bit per cell \\
Crossbar 2 weights & $1000 \times 1000$ bits & Row-major order \\
$\vdots$ & $\vdots$ & $\vdots$ \\
Crossbar 700 weights & $1000 \times 1000$ bits & Row-major order \\
Trailer & 16 bytes & Checksum \\
\bottomrule
\end{tabular}
\end{center}

A bit value of 1 indicates a conductive cell. A bit value of 0 indicates an insulating cell. The file is used directly to generate mask M3 (pillar pattern).

The total weight data size is $700 \times 1000 \times 1000$ bits = 87.5 MB.

The file is delivered to the foundry on a secure medium. The foundry loads the file into its mask generation tool, which produces the pillar mask. The mask is then used in the standard fabrication flow.

The file format is fixed. Any change to the header, body, or trailer requires coordination between the host and the foundry.

\part{Operating Principles}
%=====================================================================

\section{Write Operation (Programming at Fabrication)}

The weights are programmed at fabrication during production test. The programming occurs only once. The weights cannot be changed in the field.

\subsection{Block Programming Procedure}

For each word line:

\begin{enumerate}
    \item Enable test mode.
    \item Apply 2.22 V to the selected word line.
    \item Apply 0 V to bit lines of cells to be programmed (weight = 1).
    \item Apply 1.12 V to bit lines of cells to be inhibited (weight = 0).
    \item Hold for 10 ns (first write-verify attempt).
    \item Verify (read back, 2 ns).
    \item If failed, apply 2.52 V (second attempt).
    \item Verify.
    \item If failed, apply 2.82 V (third attempt).
    \item Verify.
    \item If failed, apply 3.11 V (fourth attempt).
    \item Verify.
    \item Disable test mode.
    \item Move to next word line.
\end{enumerate}

\subsection{Write-Verify Voltage Levels}

\begin{center}
\begin{tabular}{p{3cm}p{3cm}p{3cm}p{3cm}}
\toprule
\textbf{Attempt} & \textbf{Field} & \textbf{Voltage} & \textbf{Cumulative switch fraction} \\
\midrule
1 & 1.5 MV/cm & 2.2245 V & 0.500 \\
2 & 1.7 MV/cm & 2.5211 V & 0.875 \\
3 & 1.9 MV/cm & 2.8177 V & 0.984 \\
4 & 2.1 MV/cm & 3.1143 V & 0.999 \\
\bottomrule
\end{tabular}
\end{center}

The "Cumulative switch fraction" column is the fraction of cells that have switched by that attempt. After all four attempts, 99.9\% of cells are correctly programmed. The remaining 0.1\% are handled by ECC and by mapping the affected output channels to spare resources.

\subsection{Total Programming Time}

For the baseline device (700 crossbars, 1000 word lines each):

\begin{equation}
t_{\rm program} = 700 \times 1000 \times 21.1\ \text{ns} = 14.8\ \text{ms}
\end{equation}

The programming is performed once at wafer test.

\section{Read Operation}

\subsection{Procedure}

\begin{enumerate}
    \item Host sends the input vector to the on-chip DACs.
    \item The DACs convert each input value to a voltage in the range 0--50 mV.
    \item The word line driver applies the voltage to the selected word line.
    \item Cell current flows through the selected cells to the bit lines.
    \item The 10:1 MUX selects one bit line at a time.
    \item The comparator compares the bit line current against the reference.
    \item The ADC digitizes the resulting value to 8 bits.
    \item The digitized values are combined and sent to the host.
\end{enumerate}

\section{Compute Operation}

\subsection{Matrix-Vector Multiplication}

When voltage $V_i$ is applied to word line $i$, the current on bit line $j$ is:

\begin{equation}
I_j = \sum_i V_i G_{ij}
\end{equation}

where $G_{ij} = 1/R_{ij}$ is the cell conductance.

This is the matrix-vector product:

\begin{equation}
\mathbf{I} = \mathbf{G}^T \mathbf{V}
\end{equation}

The result is digitized by the ADC and read by the host.

\subsection{Compute Procedure}

\begin{enumerate}
    \item Host loads the input vector to the DACs (10 ns).
    \item Apply voltages to word lines (2.25 ps).
    \item Current summing on bit lines.
    \item Comparator discrimination (2.16 ns).
    \item ADC digitization (10 ns).
    \item Output vector read.
\end{enumerate}

\subsection{Throughput}

\begin{equation}
\text{Throughput} = \frac{N_{\rm active} \times 10^6}{t_{\rm compute}}
\end{equation}

For 70 active crossbars and $t_{\rm compute} = 15.67$ ns:

\begin{equation}
\text{Raw MAC/s} = \frac{70 \times 10^6}{15.67 \times 10^{-9}} = 4.47 \times 10^{15}
\end{equation}

\begin{equation}
\text{Fair MAC/s} = \frac{4.47 \times 10^{15}}{8} = 5.58 \times 10^{14}
\end{equation}

The fair MAC rate divides by 8 to convert 1-bit weights to INT8-equivalent operations.

\section{Power-On Sequence}

\begin{enumerate}
    \item Apply 1 V logic supply.
    \item Wait for power-on reset (1 $\mu$s).
    \item Load calibration values from on-chip memory.
    \item Enable the 70 active crossbars.
    \item Begin operation.
\end{enumerate}

Total boot time: $<$10 $\mu$s. The write supply is not needed during normal operation. The weights are non-volatile and need no re-programming.

\section{Power-Down Sequence}

\begin{enumerate}
    \item Complete pending operations.
    \item Remove logic supply.
\end{enumerate}

The weights are non-volatile. Power-off is instant. Power-on restores the device with no state loss.

\section{Error Handling}

\subsection{Correctable Errors}

\begin{enumerate}
    \item Correct the error using ECC.
    \item Log the event.
    \item Continue operation.
\end{enumerate}

\subsection{Uncorrectable Errors}

\begin{enumerate}
    \item Retry the operation.
    \item If retry fails, mark the affected output channel as bad.
    \item Remap the output channel to a spare channel.
    \item If no spares remain, report to host.
\end{enumerate}

\section{Redundancy}

The baseline device has 700 crossbars, of which 70 are active at any time. The remaining 630 crossbars are available for redundancy:

\begin{itemize}
    \item If a crossbar is found to be defective during test, it is mapped out and replaced by a spare crossbar.
    \item If a crossbar degrades during operation, the control logic can switch to a spare crossbar.
\end{itemize}

The spare crossbar count provides a large margin for yield and reliability.
