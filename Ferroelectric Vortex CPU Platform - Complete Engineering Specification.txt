\begin{abstract}
This document is the complete engineering specification for a general-purpose processor platform built on ferroelectric vortex memory cells.

The platform consists of two dies in a single package:

\begin{enumerate}
    \item \textbf{Main Processor:} A scalar processor with a stored-function ALU array, a pipeline, a cache hierarchy, and a register file.
    \item \textbf{Vector Co-Processor:} A 1024$\times$1024 crossbar for matrix-vector multiplication, with 0.109 GB of integrated non-volatile memory.
\end{enumerate}

The baseline platform provides:

\begin{itemize}
    \item \textbf{Clock:} 8.10 GHz
    \item \textbf{Effective IPC:} 2.614
    \item \textbf{Single-thread throughput:} 21.2 GIPS
    \item \textbf{Vector throughput:} $1.02 \times 10^{14}$ MAC/s (1-bit workloads)
    \item \textbf{Power:} 0.90 W (Main: 221 mW, Vector Co-Processor: 680 mW)
    \item \textbf{Efficiency:} 23.6 GIPS/W
    \item \textbf{Cost:} \$7.24
\end{itemize}

The platform uses standard 28 nm CMOS with hafnium zirconium oxide (Hf$_{0.5}$Zr$_{0.5}$O$_2$, HZO) atomic layer deposition. No exotic materials are required.

The document covers architecture, cell geometry and materials, fabrication flows for both dies, circuit design, operating principles, performance specifications, verification and qualification, failure modes and mitigations, packaging, and an advanced optimization configuration available separately.

The design is released openly. No patent is sought.

\textbf{This is a 6DUFT inspired technology.}
\end{abstract}

\section{Purpose and Scope}

This document is the complete engineering specification for a general-purpose processor platform built on ferroelectric vortex memory cells.

It provides every parameter, process step, circuit specification, and procedure required to build, test, and operate the baseline platform.

The document is written for:

\begin{itemize}
    \item Foundry process engineers who will fabricate the two dies.
    \item Circuit designers who will integrate the platform.
    \item Test engineers who will qualify the platform.
    \item System engineers who will deploy the platform.
\end{itemize}

No prior knowledge of any theoretical framework is required. All necessary engineering information is contained in this document.

\section{Platform Overview}

The platform consists of two dies in a single package:

\begin{center}
\begin{tabular}{p{4cm}p{5cm}p{5cm}}
\toprule
\textbf{Die} & \textbf{Function} & \textbf{Die Area} \\
\midrule
Main Processor & Scalar processor with stored-function ALU array and pipeline & 65 mm$^2$ \\
Vector Co-Processor & 1024$\times$1024 crossbar with 0.109 GB integrated memory & 54 mm$^2$ \\
\midrule
\textbf{Total} & \textbf{Two-die package} & \textbf{119 mm$^2$} \\
\bottomrule
\end{tabular}
\end{center}

\subsection{Main Processor}

The Main Processor is a scalar processor that:

\begin{itemize}
    \item Runs general-purpose code.
    \item Executes the operating system.
    \item Handles branches, caches, and control flow.
    \item Is optimized for single-thread performance.
\end{itemize}

The Main Processor uses a stored-function ALU array instead of a traditional gate-based ALU. Each ALU is a 16$\times$4 crossbar that stores a truth table implementing a specific 4-bit to 4-bit function. The truth table is programmed at fabrication.

\subsection{Vector Co-Processor}

The Vector Co-Processor is a dedicated accelerator that:

\begin{itemize}
    \item Accelerates vector and matrix operations.
    \item Provides 0.109 GB of integrated non-volatile memory.
    \item Handles DMA transfers.
    \item Is fixed at the baseline configuration.
\end{itemize}

The Vector Co-Processor uses a 1024$\times$1024 crossbar of ferroelectric cells. The crossbar stores matrix weights and performs a matrix-vector multiplication in a single parallel operation.

\section{Why Two Dies}

A single die would combine the scalar and vector functionality. Two dies are used instead because:

\begin{enumerate}
    \item The Main Processor uses the ferroelectric material for the ALU array.
    \item The Vector Co-Processor uses the ferroelectric material for the crossbar and memory.
    \item The two dies have different array layouts and different circuit requirements.
    \item Separate dies allow the platform to be upgraded by replacing only the Main Processor.
    \item Yield is better with two smaller dies than one large die.
\end{enumerate}

\section{What the Platform Is Not}

The platform is not:

\begin{itemize}
    \item A multi-core server processor. The platform has one Main Processor core. It does not have multiple cores for multi-threaded workloads.
    \item A training accelerator. The Vector Co-Processor is for inference and matrix operations, not neural network training.
    \item A complete system-on-chip. It requires external power management, clock reference, and I/O peripherals.
    \item Field-programmable. The ALU truth tables are fixed at fabrication. The instruction set is fixed.
\end{itemize}

\section{Key Advantages}

\begin{itemize}
    \item \textbf{Single-thread performance:} 21.2 GIPS at the baseline configuration.
    \item \textbf{Vector throughput:} $1.02 \times 10^{14}$ MAC/s (1-bit workloads).
    \item \textbf{Low power:} 0.90 W total, which is 139$\times$ lower than a typical desktop processor.
    \item \textbf{Low cost:} \$7.24 per chip.
    \item \textbf{Non-volatile memory:} 0.109 GB integrated, with instant boot.
    \item \textbf{CMOS compatible:} Standard 28 nm CMOS with HZO atomic layer deposition.
    \item \textbf{No exotic materials.}
\end{itemize}

\section{Key Limitations}

\begin{itemize}
    \item \textbf{Baseline single-thread throughput:} 0.91$\times$ a current flagship desktop processor.
    \item \textbf{Single-core:} No multi-core scaling.
    \item \textbf{Integrated memory capacity:} 0.109 GB.
    \item \textbf{Fixed function:} The ALU truth tables are programmed at fabrication.
\end{itemize}

\section{Platform Positioning}

The baseline platform is positioned for:

\begin{itemize}
    \item Embedded and edge applications
    \item Low-power desktop and mobile systems
    \item Vector-heavy workloads
    \item Educational and research use
\end{itemize}

An advanced optimization configuration with higher clock speed, higher throughput, and additional capability is available separately and is described at the end of this document.

\section{Main Processor Architecture}

\subsection{Overview}

The Main Processor consists of:

\begin{itemize}
    \item A stored-function ALU array (1000 ALUs, each a 16$\times$4 crossbar).
    \item A pipelined execution core.
    \item A register file.
    \item A branch predictor.
    \item An L1 cache hierarchy (64 KB instruction, 64 KB data).
    \item An L2 unified cache (1 MB).
    \item Control logic.
    \item Clock distribution network.
\end{itemize}

\subsection{ALU Array}

Each ALU is a 16$\times$4 crossbar of ferroelectric cells. The crossbar stores a truth table that implements the ALU function.

\begin{center}
\begin{tabular}{p{4cm}p{4cm}}
\toprule
\textbf{Parameter} & \textbf{Value} \\
\midrule
Rows per ALU & 16 \\
Columns per ALU & 4 \\
Cells per ALU & 64 \\
Total ALUs & 1000 \\
Total ALU cells & 64,000 \\
Function selection & Instruction opcode \\
\bottomrule
\end{tabular}
\end{center}

The ALU operation is a single read:

\begin{enumerate}
    \item The 4-bit input selects one of 16 rows.
    \item The selected row applies voltage to the word line.
    \item The crossbar computes the 4 output bits in parallel.
    \item The comparator reads each output column.
    \item The 4-bit result is latched.
\end{enumerate}

Each ALU implements one specific 4-bit to 4-bit function. The function is selected by the instruction decoder. Since there are only 256 possible 4-bit to 4-bit functions, and 1000 ALUs available, each function is implemented approximately 4 times. This gives redundancy.

\section{Instruction Execution}

\subsection{Instruction Procedure}

\begin{enumerate}
    \item Instruction fetch (L1I cache access).
    \item Instruction decode (opcode, operands).
    \item Operand fetch (register file read).
    \item Execute (ALU truth table read).
    \item Memory access (L1D cache, if needed).
    \item Writeback (register file write).
    \item Branch resolution (if branch).
    \item Retire.
\end{enumerate}

\subsection{Execute Timing}

\subsection{Clock Frequency}

\begin{equation}
f = \frac{1}{123.5\ \text{ps}} = 8.10\ \text{GHz}
\end{equation}

\section{Vector Compute Operation}

\subsection{Procedure}

\begin{enumerate}
    \item Load input vector to DACs (1 ns settling).
    \item Apply voltages to word lines (0.034 ns).
    \item Current summing on bit lines.
    \item TIA converts current to voltage (0.265 ns).
    \item ADC digitizes (10 ns).
    \item Output vector read.
\end{enumerate}

\subsection{Compute Time}

\begin{equation}
t_{\rm compute} = 0.034 + 0.265 + 10 = 10.3\ \text{ns}
\end{equation}

\subsection{Vector Throughput}

\begin{equation}
\text{Throughput} = \frac{1{,}048{,}576}{10.3 \times 10^{-9}} = 1.02 \times 10^{14}\ \text{MAC/s}
\end{equation}

\section{Programmable Function Selection}

Each ALU implements one specific 4-bit to 4-bit function. The function is selected by the instruction decoder.

Since there are 256 possible 4-bit to 4-bit functions, and 1000 ALUs are available, each function is implemented approximately 4 times. The instruction decoder selects the appropriate ALU for each opcode.

\section{Write Operation (Programming at Fabrication)}

The ALU truth tables are programmed at fabrication during production test. The programming occurs only once. The truth tables cannot be changed in the field.

\subsection{Write-Verify Voltage Levels}

\begin{center}

\bottomrule

\subsection{Programming Time}

With 100 cells programmed in parallel:

\begin{equation}
t_{\rm program} = \frac{64{,}000 \times 22.2\ \text{ns}}{100} = 14.2\ \mu\text{s}
\end{equation}

\section{Power-On Sequence}

\begin{enumerate}
    \item Apply 1 V logic supply.
    \item Wait for power-on reset (1 $\mu$s).
    \item Apply write voltage supply (only during programming).
    \item Load calibration from on-chip memory.
    \item Begin operation.
\end{enumerate}

Total boot time: $<$10 $\mu$s.

\section{Power-Down Sequence}

\begin{enumerate}
    \item Complete pending operations.
    \item Store critical data to non-volatile memory.
    \item Remove write supply.
    \item Remove logic supply.
\end{enumerate}

Non-volatile memory preserves all state. Power-off is instant.

\section{Error Handling}

\subsection{Correctable Errors}

\begin{enumerate}
    \item Correct the error using ECC.
    \item Log the event.
    \item Continue operation.
\end{enumerate}

\subsection{Uncorrectable Errors}

\begin{enumerate}
    \item Retry the operation.
    \item If retry fails, mark block as bad.
    \item Use a spare block.
    \item If no spares remain, report to OS.
\end{enumerate}
